# Production runbook

## До релиза

1. Использовать Node и pnpm закреплённых версий.
2. Выполнить `pnpm install --frozen-lockfile --ignore-scripts`.
3. Выполнить `pnpm release:check`.
4. Запустить `pnpm start` на результате сборки и пройти smoke-сценарии из `RELEASE_CHECKLIST.md`.
5. Проверить карточку `/og.png`, favicon, canonical URL и защитные заголовки на финальном домене.

## Наблюдаемость

Игра не отправляет телеметрию по принципу privacy-by-default. Для оценки доступности сервиса используются только платформенные метрики Cloudflare/Sites: доля ответов 5xx, p95 latency Worker и успешность раздачи статических ассетов.

Рекомендуемые пороги:

- 5xx > 1% за 5 минут: критический инцидент;
- p95 Worker > 1 500 ms за 15 минут: деградация;
- недоступность `/` в двух регионах: критический инцидент;
- рост client-side ошибок оценивается только после явного решения о подключении privacy-safe telemetry.

## Инцидент

1. Зафиксировать время, версию и опубликованный URL.
2. Проверить `/`, JS/CSS chunks и HTTP-заголовки.
3. Если сбой относится к новой версии, откатить deployment через платформенный механизм Sites.
4. Воспроизвести на зафиксированном lockfile командой `pnpm release:check`.
5. Исправить первопричину, добавить regression test, повторить полный цикл и выпустить patch-версию.

## Восстановление пользовательского прогресса

Серверной копии нет. До изменений схемы сохранения нельзя менять ключ или `SAVE_VERSION` без миграции. Если повреждение обнаружено, приложение безопасно предлагает новый мир; автоматическое «исправление» неподтверждённых полей запрещено, чтобы не создавать невалидное состояние.

## Откат

Откат к предыдущему deployment безопасен, пока версия сохранения совместима. Если новая версия уже записывает другой формат, предыдущий runtime должен либо уметь читать его, либо релиз обязан использовать новый ключ с миграцией. Для 1.0.0 формат — v1.
